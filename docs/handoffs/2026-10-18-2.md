# Session Handoff: 2026-10-18 (session 2)

## Summary

Defined the MVP, chose the stack, and shipped a first running app. MyTrails is
now a native Kotlin Android project that builds from the command line and shows
a MapLibre map with the live GPS position on the emulator. It has not been run
on a physical phone yet, and there is no automated build, lint or test in CI.
The owner is new to Android, so Claude writes the code and the owner reviews.
Next session starts the proper development setup (see Next actions).

## Current state

- `main` is at `5292916`. Build with `./gradlew assembleDebug`; see the
  Commands section of `CLAUDE.md` for JDK, SDK and emulator details.
- Toolchain: JDK 21 (Temurin) in `~/.local/jdks/jdk-21.0.12.1+1`, not on
  `PATH`, so set `JAVA_HOME`. Android SDK in `~/Android/Sdk` (platform 36,
  build-tools 36, `adb`, emulator). Gradle 8.14.3 via the wrapper.
- Emulator AVD `phone` (Pixel 7, API 36, GPS on). Start it with a window
  (`emulator -avd phone`), because the owner wants to watch. Fake GPS with
  `adb -s emulator-5554 emu geo fix <lon> <lat>`.
- App: map from MapLibre's online demo style (coarse shapes, needs network),
  permission prompt, marker that follows position with zoom 12.
- `GpsLocationEngine` requests the platform GPS provider directly. MapLibre's
  default engine requested balanced accuracy from the fused provider, which
  never produced a fix on the emulator and can resolve to Wi-Fi or cell
  positions on a phone.
- Known limits: no tests, no lint, no CI build job (`repo-hygiene` does not
  compile anything), one deprecation warning (`LocalLifecycleOwner`), the
  map view's lifecycle handling is minimal, no background tracking, no offline
  maps, not verified on a physical phone.
- Docs inconsistency: ADR 0001 says files are named `YYYY-MM-DD_short-title.md`
  but `docs/decisions/README.md` says `NNNN-short-title.md`. Files follow the
  README. Not fixed yet.
- Template leftovers still open: README "Using this template" section,
  LICENSE (template GPL-3.0, unconfirmed), `CONTRIBUTING.md` Setup,
  `dependabot.yml` ecosystem entry.

## Risks or decisions needed

- Offline tile format and source (for example PMTiles or MBTiles from an
  OSM-derived extract) needs its own ADR before offline maps start.
- Routing engine for driving navigation needs its own ADR later; keep it in
  mind when picking map data.
- Background location on current Android: foreground service type, notification,
  and battery behaviour. Needs a design note before track recording.
- Release signing: the release build type uses the debug key. Fine for
  sideloading now, but updates only install over the same key, so keep
  `~/.android/debug.keystore` backed up or move to a dedicated key soon.
- The demo map style needs network. Do not treat the current map as offline
  capable.
- License is still the template's GPL-3.0; owner to confirm.
