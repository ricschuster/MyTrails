## Current state

### App

- All four MVP features from the brief exist: live position with follow and
  compass heading, recording in a foreground service, saved tracks with GPX export
  and import, and an offline map from PMTiles files with optional hillshade.
  A Re-centre button appears after a pan and resumes following.
- Package `ca.mytrails.app`, version 0.1.0, debug build, `main` at the roadmap
  merge. CI checks are `repo-hygiene` and `build` (lint, ktlint and tests run in
  the build job).

### Phone test (Pixel 9 Pro, API 37)

- Debug build installed. Roberts Creek `roberts-creek.pmtiles` and
  `roberts-creek-terrain.pmtiles` were pushed to
  `/sdcard/Android/data/ca.mytrails.app/files/regions/` (create the folder with
  `adb shell mkdir -p` after launching the app once). Sizes matched the emulator
  copies (1,379,250 and 23,412,161 bytes). Hillshade and the offline map render
  on the phone.
- One recording: 16:42:20 to 16:53:31, 11 minutes, 795 m, 145 points, one
  segment, state `completed`. Walking laps around a house, so the points sit in a
  box of about 25 m while the path adds up to 795 m. The phone was unplugged and
  the screen was off. Median gap between points 4 s, longest 10 s, no gap over
  15 s. Median accuracy 4.1 m, worst 24 m, median speed 1.25 m/s.
- Verdict: the foreground service survives screen-off on battery while walking.
  Not covered: more than an hour, stationary Doze, dense tree cover, battery
  drain, and the Pixel's battery optimisation setting. Issue #62 holds the long
  outing test.
- The test track is still saved on the phone. Delete it from the Tracks screen
  if it is in the way.
- How the numbers were read: the phone has no `sqlite3`. Copy the database with
  `adb -s <serial> exec-out run-as ca.mytrails.app cat databases/tracks.db` (and
  the `-wal` and `-shm` files) and read it locally with Python's `sqlite3`.
  Tables are `track` (id, name, startTimeMillis, endTimeMillis, state,
  distanceMeters, durationMillis) and `point` (trackId, segment, latitude,
  longitude, timeMillis, altitude, accuracyMeters, speedMetersPerSecond).

### Emulator

- The default GPU mode crashed the emulator once while the map screen was open.
  The log showed `gles_v2_imp.cpp ... error null ctx` after MapLibre created a
  Vulkan device, then a SIGSEGV in `libgfxstream_backend.so`
  (`ColorBufferGl::create`, `TextureResize`). This happened during the session
  after the map went blank. With `-gpu swiftshader_indirect` the same walk ran
  cleanly, and the map stayed rendered. An earlier emulator crash on Oct 17 used
  `-gpu host`. It may be a one-off; it was not reproduced on demand.
- A launch that is safe for the session:
  `setsid nohup ~/Android/Sdk/emulator/emulator -avd phone -gpu swiftshader_indirect -no-snapshot-save > log 2>&1 < /dev/null & disown`.
  CLAUDE.md Commands has this note.
- Map tiles can take several seconds to draw after a launch or a fix. A blank or
  partly drawn map in the first seconds is not a bug.

## Risks or decisions needed

- Assumptions in the roadmap are defaults, not answers: mountain biking and
  hiking equally, strictly offline, Bluetooth sensors later. Confirm or change
  them, since they set the order.
- Several unrelated programs on the desktop have segfaulted since Oct 3 (Blender,
  node, Chromium, Kate, Firefox, Claude, qemu), and two Claude crashes and a
  Firefox crash landed within a minute of an emulator launch earlier today. No
  MCE, EDAC or OOM entries were logged. Bad RAM or an unstable memory profile is
  possible and untested. Suggested: memtest86+, XMP/DOCP off, KSM off
  (`/sys/kernel/mm/ksm/run` is 1).
- Whether to set `hw.gpu.mode = swiftshader_indirect` in the AVD config as the
  default is undecided.
- The terrain licence texts (Open Government Licence - Canada and Copernicus) are
  unread. That blocks the elevation note (#63), contours and slope layers (#71),
  and clears hillshade.
- OSM trail tags are sparse (about 4% of ways carry a difficulty tag in the test
  area). Tap to identify (#56) will show "unknown" often, which is why the own
  ratings feature (#75) is in the plan.
- Housekeeping: milestones M1 to M5 are finished but open. A stale local and remote
  branch `docs/session-5-handoff` exists with an older handoff already on `main`;
  it can be deleted. `enableLocation` adds its tracking listener again on every style
  reload (harmless, untidy). Release signing uses the debug key (back up
  `~/.android/debug.keystore`). The license is still GPL-3.0 from the template;
  owner to confirm.
